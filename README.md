## 这是什么

思源学堂 2.0 的部分课程附件由网页前端动态加载，直接保存网页并不能完整保存课件、作业和录像。
这个项目把你在浏览器里已经能正常访问的课程资源统一整理下来：

清单生成 · 课件与作业批量下载 · 课堂录像与课程回放 · 按章节归类 · 断点续传 ·
失败重试 · 大小与 SHA-256 校验 · 增量更新 · `--dry-run` 预览

整个流程使用你本人正常登录后获得的会话状态。
附件不在 DOM 里而是分三类来源（活动附件数组 / 活动正文内嵌 / 直播回放地址），只看一类会漏——
课件 PDF 几乎全在正文内嵌那一类，只看附件数组会误判成「这门课没有课件」。

## 使用范围与说明

本项目主要用于个人学习过程中对课程资料进行备份、归档和离线整理。
使用时请遵守学校相关规定、课程资源版权要求以及教学平台的正常使用规则。

- 仅访问当前登录账号**有权访问**的课程与资源，不绕过统一身份认证或平台权限控制；
- 不提供越权访问、权限提升或批量探测无权限课程的功能；
- 不进行高并发请求，并对 401、403 等权限类错误停止重试；
- 仓库不包含任何课程课件、录像、Cookie 或账号密码；下载所得资料不应再通过本项目公开传播。

本项目是一个客户端自动化与资料整理工具，并不会改变服务器对课程、附件和录像资源的权限判断。
使用者应自行确认其对相关课程资源具有合法、合规的访问和使用权限。

## 装成 Skill（推荐用法）

> 帮我把这门课的资料都下载下来，课程链接：`https://lms.xjtu.edu.cn/course/<课程ID>/index`

AI 会自动完成「登录 → 干跑列清单 → 等你确认 → 下载 → 按章归类」，并在此过程中遵守
本项目的使用边界与负载控制策略。

### 安装：把文件夹放进助手的 skills 目录

`SKILL.md` 是通用的 Skill 格式（YAML frontmatter + 正文），主流 AI 编程助手都认。
把整个 `xjtu-siyuanxuetang-grab` 文件夹放进对应目录：

| 工具 | 放入目录 |
|---|---|
| WorkBuddy | `~/.workbuddy/skills/xjtu-siyuanxuetang-grab/` |
| Claude Code | `~/.claude/skills/xjtu-siyuanxuetang-grab/` |
| Codex | `~/.codex/skills/xjtu-siyuanxuetang-grab/` |
| 其他 | 该助手约定的 skills / prompts 目录 |

```
Windows:       C:\Users\<你>\.<助手目录>\skills\xjtu-siyuanxuetang-grab\
macOS / Linux: ~/.<助手目录>/skills/xjtu-siyuanxuetang-grab/
```

装好后无需额外配置，助手匹配到「下载课程资料」这类场景时会自动读取 `SKILL.md` 执行。
`SKILL.md` 里已写明使用边界（仅访问有权访问的课程、不并发、不重试权限错误），
**装成 Skill 不会绕过这些约束**。

### 装好后先自检一次

```bash
python scripts/lms_selfcheck.py --course <课程ID>
```

默认**只做离线检查**（Python 版本 / 脚本完整性 / playwright / 浏览器 / 缓存目录 /
登录态形状 / 浏览器 profile），不碰服务端；加 `--online` 才额外打一次接口确认登录态
在服务端仍有效。输出按 `✓ 通过` / `! 警告` / `✗ 失败` 分三级，**每个不正常项都直接给出
可复制的修复命令**；退出码 `0` 无失败项、`1` 有失败项。

**看到 `✗` 就先修完再往下走**——否则登录/下载阶段的报错会指向错误的方向。
登录态检查区分五种情况（不存在 / 损坏 / cookies 为空 / 域不匹配 / 正常），
这几种修法不同，所以不合并成一句「登录态有问题」。

### 不想装 Skill 的两种替代

| 方式 | 做法 | 适合 |
|---|---|---|
| **Prompt** | 把 [`prompt.md`](prompt.md) 贴进任意对话式 AI，改掉两处 `【】` | 助手不支持 Skill，或只想临时用一次 |
| **命令行** | 直接 `python scripts/lms_fetch.py ...`（见下方「快速开始」） | 自己控制每一步，或做脚本化/定时任务 |

此时 `SKILL.md` 相当于一份完整的操作手册，`prompt.md` 是可复制的通用 Prompt。

## 快速开始

```bash
pip install playwright                                                      # 只有登录脚本需要
python scripts/lms_selfcheck.py --course <课程ID>                            # 1. 自检（离线）
python scripts/lms_login.py    --course <课程ID>                            # 2. 登录（弹浏览器手动过认证）
python scripts/lms_fetch.py    --course <课程ID> --out "./课程资料" --dry-run # 3. 干跑看清单
python scripts/lms_fetch.py    --course <课程ID> --out "./课程资料"          # 4. 下载（幂等，可反复跑补件）
```

第 1 步不是可选项：它把「环境没装好」和「平台没给权限」区分开，跳过的话这两类问题的
报错会互相伪装，排查很费时间。用系统自带的 Edge / Chrome 时**不需要** `playwright install`。

**想要开箱就是分好章的结构？** 加 `--organize`（先配 `--dry-run` 看归类对不对）。
章节号从活动标题和文件名两处抽，优先采信标题，覆盖 `第1章 / 第一章 / 第1讲`、
`Lec11 / Lecture 3 / Chapter 2 / Unit 5`、纯数字开头 `01-绪论` 等写法。
会主动避开 `实验1-…`、`Project 1 …`、`大实验作业` 这类**假章号**（前面是实验/项目编号，
不是章次），认不出章号的进 `其他/`。

**录像**默认一起下，落到独立目录：

| 类型 | 落到 | 说明 |
|---|---|---|
| `online_video` 课堂录像 | `录像/<活动标题>/` | 普通附件，复用下载逻辑 |
| `lecture_live` 直播回放 | `回放/<活动标题>/` | 独立录播域名，默认只下屏幕录制机位，`--all-cameras` 加教师机位 |

录像往往几百 MB（90 分钟的回放可达数百 MB），**下之前先看干跑的体积**；只要讲义加 `--no-video`。
录像与回放都不参与 `--organize`——标题认不出章号，硬套只会全堆进 `其他/`。

```
课程资料/
├── 课件/第01章 绪论/
├── 作业/第07章作业 Canny边缘检测/
├── 录像/第1讲 课程介绍/第1讲课程介绍.mp4                        ← online_video
└── 回放/<日期>-<课程名>/<日期>-<课程名>-<时间戳>-encoder.mp4      ← lecture_live
```

> 回放文件名里的时间戳不是装饰：同一天的多个活动 **`title` 可能完全相同**，
> 只有开课时间字段不同。只用标题命名会让多节课互相覆盖、只剩最后一节。

## 参数与环境变量

| 参数 | 作用 |
|---|---|
| `--course <ID>` | 课程 ID（课程链接里的数字） |
| `--out <目录>` | 输出目录 |
| `--organize` | 自动按章整理：`课件/第01章 xxx/`，认不出放 `其他/` |
| `--list-only <文件>` | 只列清单不下载，导出 `.json` 或 `.csv` |
| `--manifest <文件>` | 下载后把清单 + sha256 写入 `.json` 或 `.csv` |
| `--retries N` | 单文件重试次数，默认 3（指数退避） |
| `--no-verify` | 跳过下载前的登录态探测 |
| `--exclude "2020\|2021\|2022"` | 文件名正则，命中跳过（清理旧版作业） |
| `--no-video` | 跳过录像与回放，只要讲义时用 |
| `--all-cameras` | 回放连「教师机位」一起下 |
| `--split-projects` | 项目/大作业压缩包（`Project1.zip`、`大作业.zip` 这类）单独进 `项目/`；普通 zip 如 `资料.zip` 不受影响 |
| `--layout flat` | 平铺，不按活动建子文件夹 |
| `--dry-run` | 只打清单不下载；配 `-v` 会显示归类后的目标目录 |
| `-q` / `--quiet` | 不显示下载进度 |
| `--activities <json>` | 用本地清单，省一次请求 |
| `--base <url>` | 换平台地址（**别的 TronClass 学校可直接复用**） |

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `LMS_BASE` | `https://lms.xjtu.edu.cn` | 平台地址 |
| `LMS_CACHE` | `~/.lms-grab` | 登录态 / profile 目录 |
| `LMS_BROWSER` | 自动探测 | 强制指定浏览器 exe 绝对路径 |

浏览器探测顺序：`LMS_BROWSER` → 系统 Edge → 系统 Chrome → playwright 自带 chromium
（Windows / macOS / Linux 三分支都已覆盖）。

## 下载的可靠性设计

下载一门课动辄几十个文件、几百 MB，中途出问题很常见。这几层是刻意加的：

**断点续传。** 中断后带 `Range` 头从断点继续，残片保留在 `<文件名>.part`，
续传时残片会计入 sha256——否则哈希校验就是空的。服务端若忽略 `Range`（返回 200 全量），
脚本丢掉残片重下；回放服务端还会按自己的块边界**扩大请求区间**（返回起点比请求的更靠前），
脚本以响应里的 `Content-Range` 为准、丢弃重叠段再续写；若返回起点跳到残片末尾之后
（出现缺口），直接判这次续传无效、作废残片重下——绝不把对不上的数据 append 进文件。

**失败重试。** 超时、连接中断、5xx 退避重试（默认 3 次）。但 **403 / 404 不重试**——
那是平台侧的限制（无权限或已删除），重试只是浪费时间。

**失败与 N/A 分得清。** 取元信息时 403 / 404 标 `N/A` 跳过（平台确实没给这个文件）；
401 明确报「登录态失效，请重新登录」；超时、连接错误、5xx、JSON 解析失败一律计为
**FAIL** 并计入退出码 4——接口临时抖动不会被伪装成「平台没权限」，
不会出现 `fail=0` 却漏了一堆文件的假象。

**登录态探测。** 下载前先探一次接口。登录过期会明确报「登录态已失效，跑 `lms_login.py`」，
而不是让每个文件都显示成 `N/A` 让人误以为平台没给权限。退出码 `3` 专门表示这个情况。

**完整性校验。** 平台不提供官方哈希响应头，可用的信号是 `etag`。脚本用它和元信息大小
交叉验证，并把本地算出的 sha256 写进 `--manifest` 供事后核对。

**已有文件先比对大小。** 服务端声明了大小时，本地文件**大小相等**才算下完，不等就重下——
上次下到一半留下的 20MB 不会被当成完整的 100MB 永远跳过。

**回放完整性。** 回放拿不到官方哈希，只能比对「服务端声明的总长」与实得字节数。
差异在 8% 以内视为自然短读，超出直接判失败：不落盘成最终 mp4、保留 `.part` 供下次续传——
截断的视频不会被当成完整文件留在磁盘上。

**文件名安全。** 长文件名截断时保住扩展名，非法字符替换，路径穿越会被拍平，
Windows 保留设备名（`CON.pdf` / `NUL.txt`）统一加下划线前缀，三个平台落盘结果一致。

**同名不覆盖。** 不同活动下的同名附件落到同一路径时，自动改用带 uid 的确定性后缀
（`讲义~123.pdf`），第二个文件不会被静默跳过。

## 安全与负载控制

项目有意避免可能给教学平台造成额外压力的行为：默认串行处理较大的录像资源；
遇到 401 / 403 / 404 不做高频重试；网络异常采用有限次数的退避重试；
支持断点续传避免重复传输；建议先 `--dry-run` 检查资源数量与体积。

请勿修改程序用于高并发扫描、批量枚举课程或其他超出正常个人学习用途的操作。

## 使用中的注意事项

1. **附件来源不止一处。** 课件 PDF 藏在活动正文里，只看附件数组会误判成「这门课没有课件文件」。
2. **文件名要从平台接口的元信息取，别从正文链接文字猜。** 正文显示名与实际文件名常不一致。
3. **N/A 与 FAIL 是两回事。** 个别附件 403 / 404 标 `N/A` 跳过；超时、5xx、JSON 解析失败
   是**获取失败**，计入 `FAIL` 和退出码 4，换个时间重跑就能补上——结尾看一眼 `ok/fail/skip` 再下结论。

另外：启动 URL **不要带 `#/`**——带 hash 会让页面路由异常，渲染进程假死。

## 隐私与凭据

本项目不会要求用户将账号密码写入代码。登录由浏览器和学校统一身份认证系统完成，
随后只在用户本机保存必要的会话状态。

登录态文件就是**你的登录凭据**：拿到它的人等于拿到了你的账号会话，不要分享、
不要截图外发、不要提交到任何仓库。`lms_login.py` 只保存下载所需的最小内容
（目标域名的 cookie），并在 POSIX 系统上把文件权限收成 `0600`。

任何与登录凭据、Cookie、浏览器 profile 相关的文件都已通过 `.gitignore` 排除
（`state_*.json` / `activities_*.json` / `profile_*/` / `storage_state.json` /
`cookies*.json` / `*.har` / `.lms-grab/`），不应提交到 Git 仓库。

一个文件里（域名 / 缓存目录 / 浏览器探测），换台电脑直接可用。

## 开发者：跑测试

抓取逻辑最容易出回归，所以测试是**纯离线**的，不需要网络和登录态：

```bash
python tests/test_organize.py     # 22 个用例
python tests/test_fetch.py        # 121 个用例
python tests/test_selfcheck.py    # 20 个用例
```

`test_fetch.py` 用假 opener 脚本化服务端行为，能测「第一次超时第二次成功」
「服务端把 Range 起点从 5MB 挪到 4MB」这类真实环境里很难复现的路径；
时区相关用例会临时切换 `TZ` 验证，不依赖跑测试的机器在哪。

CI 在 push / PR 时自动跑三平台 × 三个 Python 版本，外加一步隐私自检。
详细的覆盖矩阵、CI 配置说明见 **[docs/MAINTAINING.md](docs/MAINTAINING.md)**。
